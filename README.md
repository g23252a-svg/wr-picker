# WR Picker v10.0

와일드 리프트 드래프트에서 라인, 아군, 상대, 밴을 입력하면 **매일 자동 갱신되는** 랭크 구간별 통계와 실제 상성 데이터, 전술 브리핑, 그리고 **내 실제 성과**를 함께 계산하는 설치형 웹 앱입니다.

## v10.0 개선 (엔진이 자기 점수를 옛 버전으로 채점하고 있었다)

v9는 "엔진이 자기 성적표를 낸다"며 추천 점수와 실제 승률을 나란히 놓았습니다. 그 성적표를 믿고 다음 개선을 정하려다, 성적표 자체가 틀렸다는 걸 발견했습니다.

### 성적표가 채점하던 건 지금 엔진이 아니었다

채점 대상이 판마다 저장해둔 `scoreSnapshot.total`이었습니다. 그 값은 **그 판을 기록할 당시 살아 있던 엔진**이 남긴 것입니다. 실사용 111판의 스냅샷에는 `3.0.0`부터 `7.1.0`까지 **아홉 개 엔진 버전**이 섞여 있었고, 32판은 스냅샷 자체가 없어 채점에서 아예 빠져 있었습니다. "지금 점수를 믿어도 되나"를 묻는 표가 박물관을 채점하고 있었던 셈입니다.

- **과거 전 판을 지금 엔진으로 다시 채점합니다.** 채점 대상 79판 → **111판**. 엔진을 고치면 이 표가 곧바로 따라 움직입니다
- **각 판은 그 판 직전까지의 전적만 보고 채점합니다.** 전체 전적으로 채점하면 이긴 판의 챔이 숙련 점수를 더 받아 점수가 저절로 맞아 보입니다 — 결과를 미리 아는 채점입니다
- 점수 구간도 고정값이 아니라 **내 점수 분포의 사분위**로 자릅니다. 엔진을 고치면 점수 분포가 통째로 옮겨가므로 고정 경계는 금세 한쪽으로 쏠립니다
- 채점 비용은 111판 기준 14ms입니다

### 축별 성적표 — 어느 축이 실제로 맞히고 있나

총점만 검증하면 어느 축이 틀렸는지 영영 알 수 없습니다. 축마다 **순위 일치도**(이긴 판의 축 값이 진 판보다 높을 확률)를 냅니다. 0.50이 동전던지기입니다.

| 축 | 순위 일치도 | 표본 |
| --- | --- | --- |
| 숙련 | 0.55 | 111판 |
| 팀 조합 | 0.55 | 108판 |
| 메타 | 0.52 | 111판 |
| **상성** | **0.41** | 107판 |

상성 축은 방향이 뒤집혀 있었습니다 — 올려야 할 때 내리고 있었다는 뜻입니다.

### 축의 발언권을 '맞혀 온 만큼'으로

v9.1은 숙련 축의 발언권을 근거의 **양**에 비례시켰습니다. 그런데 양이 아무리 많아도 방향이 틀린 축은 그대로 크게 말합니다.

- 축마다 성적을 매겨 **못 맞히는 축의 가중치를 자동으로 깎습니다**(최대 −50%). 올리는 쪽은 +15%까지만 엽니다 — 축이 잘 맞힌다는 증거보다 못 맞힌다는 증거가 훨씬 값싸게 얻어지기 때문입니다
- **30판 미만인 축은 건드리지 않고**, 표본이 적을수록 보정 폭이 자동으로 줄어듭니다(80판에서 최대)
- 지금 적용값은 설정 화면과 분석 탭에 **숫자로 그대로 표시**하고, `슬라이더 그대로`로 끌 수 있습니다
- 실사용 기준 적용값: 숙련 110% · 팀 조합 110% · 메타 103% · **상성 83%**

### 라인 상성 축의 상한이 없었다

v9는 팀 단위 상성을 ±22로 잘랐습니다("고기동·락다운·폭딜은 대개 같은 조합을 다른 각도에서 세는 것"). 그런데 **정작 더 심하게 겹쳐 쌓이는 쪽은 라인 상성이었고, 거기엔 상한이 없었습니다.**

클래스 매트릭스(±14) + 가이드 상성(±14) + 기동 보정(±12) + 사거리(±12) + 원거리 우위(±5) + 유명 상성(±8) + 특성 매치업(±12) — 전부 "이 매치업이 유리한가"를 다른 각도에서 세는 항목인데 그대로 합산됐습니다. 실사용에서 **최대 +36**까지 나왔고, 그 하나만으로 상성 축(50±50)을 포화시킬 수 있었습니다.

- **±16으로 자릅니다.** 실측 `|라인 상성|` 중앙값은 8, 90분위는 17이라 신호는 남고 꼬리만 잘립니다. 최대 기여 36 → 16
- **봇 듀오는 1v1 라인이 아닙니다.** 정글이 이미 `×0.5` 감쇠를 받는 이유("지속 라인전이 없다")와 같은 이유가 봇에도 있습니다 — 원딜·서폿의 라인전은 상대 서폿 한 명과의 상성이 아니라 2v2 조합으로 갈립니다. 실사용에서 파이크(서폿)가 럭스 상대로 라인 상성 +27을 받았지만 그런 판들의 승률은 2/8이었고, 라인 상성의 순위 일치도는 서폿 0.28 / 원딜 0.21로 다섯 라인 중 최하위였습니다. `×0.6`으로 감쇠합니다
- 라인 상성 +8 이상이던 판의 승률 41%(13/32) → 48%(12/25)

### 가이드 상성이 라인을 가리지 않고 적용됐다

`guides.json`의 카운터 관계 **414건 전부에 라인 태그**가 붙어 있습니다(`solo`/`jungle`/`mid`/`duo`/`support`). 그 챔의 가이드가 다루는 라인이라는 뜻인데, 엔진은 그 태그를 버리고 있었습니다. 서폿 럭스의 카운터 목록(파이크·나미·카르마)이 **미드 럭스를 상대할 때도 그대로 ±14**로 적용됐습니다.

- 같은 라인 자료면 원래대로 ±14, 다른 라인 자료면 ±5로 낮추고 `(다른 라인 자료)`라고 적습니다. 버리지는 않습니다 — 라인이 달라도 방향이 유지되는 상성이 많습니다

### 분석 탭 막대가 한 번도 그려지지 않았다

`.bf`(막대 채움)가 `<span>`인데 `display:block`이 없어 인라인 박스로 잡혔습니다. 인라인 요소에는 `width`·`height`가 적용되지 않으므로, **분석 탭이 생긴 v7.1 이후 모든 막대가 빈 트랙으로만 남아 있었습니다.** 승률 62%짜리 줄도 0%처럼 보였습니다. 한 줄 고쳤고, 분석 탭의 모든 카드가 같이 살아났습니다.

- 축별 성적표 줄에서 `발언권 83%`가 `발 / 언권 83%`로 쪼개지지 않도록 값 칸을 넓혔습니다(v9.1에서 배지에 있던 것과 같은 문제)
- `가중치 기본값` 버튼이 목표 설정까지 함께 되돌리던 것을 고쳤습니다 — 가중치가 아닌 항목은 건드리지 않습니다

### 검증 (실사용 시드 111판, 매 판을 그 시점 정보만으로 다시 채점)

| | v9.2 | v10.0 |
| --- | --- | --- |
| 총점 순위 일치도 | 0.52 | **0.57** |
| 점수 상위 절반 / 하위 절반 승률 | 58% / 47% | **60% / 47%** |
| 상성 축 순위 일치도 | 0.39 | **0.41** |
| 라인 상성 최대 기여 | +36 | **+16** |
| 채점된 판 | 79 | **111** |

축 보정을 끄면 0.561, 켜면 0.569입니다. 보정을 과거 절반으로만 학습해 나머지 절반에 적용하는 방식(walk-forward)으로도 네 개 분할 모두에서 켠 쪽이 앞섰습니다.

상성 축은 고친 뒤에도 여전히 0.41입니다. **아직 제 몫을 못 하고 있다는 뜻이고, 그래서 자동 보정이 발언권을 83%로 깎아 두고 있습니다.** 판이 쌓이면 이 숫자는 스스로 움직입니다.

## v9.2 개선 (이긴 판에 누른 성과 등급이 무효였다)

"성과에 따라 추천이 바뀌느냐"는 질문을 확인하다 찾은 결함입니다. 답은 "바뀌지만, 진 판에서만"이었습니다.

성과 등급은 **숙련 축**을 통해서만 추천에 반영됩니다(메타·조합·상성 축은 건드리지 않습니다). 그런데 이긴 판에서는 등급을 뭘 눌러도 점수가 1도 움직이지 않았습니다.

원인은 "이긴 판은 성과가 나빠도 깎지 않는다"는 하한 보장이 **상한 노릇까지** 하고 있었다는 것입니다. 기존 식 `max(승패값, 승패값×0.4 + 성과×0.6)`에서 이긴 판이 하한(0.74)을 넘으려면 성과값이 0.74를 넘어야 했는데, 그 조건을 만족하는 등급은 MVP(1.00)뿐이었습니다. 잘함(0.68)·SVP(0.72)·보통(0.50)·부진(0.18)은 전부 하한에 잘려 무효였습니다.

실사용 성과 입력 42판 중 **26판(62%)이 아무 효과도 없었습니다** — 특히 이긴 판에 누른 `잘함` 18번이 전부 무시됐습니다.

- 이긴 판에서는 **`보통`을 기준점으로 두고 그 위쪽만 가산**합니다. 하한은 구조적으로 보장되고(가산값이 0 이상), MVP 값은 예전과 같습니다
- 등급 한 판의 효과 — 이긴 판: 보통·부진 0, 잘함 +0.056, SVP +0.069, MVP +0.156. 진 판: 부진 −0.048, 보통 +0.144, 잘함 +0.252, MVP +0.444 (승패만 있을 때 대비)
- 검증: 소나에 승리 3판을 더할 때 무등급 65 / `잘함` 67 / `MVP` 69로 갈립니다. 예전에는 셋 다 65였습니다
- `perfValue`를 정규식이 아니라 **실제로 실행해서** 검증하는 회귀 테스트를 넣었습니다. 이번 결함은 기존 정규식 테스트를 통과하면서도 동작하지 않던 종류입니다

## v9.1 개선 (내 실적이 메타를 이길 수 있게)

v9.0으로 상성 축을 고친 뒤 실사용 150판을 적재한 상태에서 각 라인의 추천 순위를 뽑아보니, 더 근본적인 문제가 드러났습니다.

**원딜 1순위가 스몰더(내 실적 0승 5패)였고, 실제로 이기는 제리(7판 71%)는 9위였습니다.** 미드에서는 세라핀(5판 80%)이 18위, 정글에서는 마오카이(6판 67%)가 18위였습니다.

원인은 가중치가 아니라 **축의 눈금**이었습니다. 숙련 축은 실질 43~63(폭 20)만 움직이는데 메타 축은 28~84(폭 56)를 움직였습니다. 같은 가중치를 줘도 메타가 3배 세게 밀 수밖에 없습니다.

- **불확실성을 두 번 반영하던 것을 한 번으로.** 숙련 값은 사전분포로 이미 표본이 적을수록 50 쪽으로 당겨지는데, 거기에 `shrink`를 또 곱하고 있었습니다. 같은 불확실성을 값에서도 깎고 가중치에서도 깎으면 값이 중립 근처 좁은 띠를 벗어나지 못합니다. 값에서는 빼고, **표본이 적다는 사실은 가중치로만** 반영합니다
- **숙련 축의 발언권을 근거의 양에 비례시킵니다.** 15판을 해본 챔과 한 번도 안 해본 챔이 똑같이 35% 가중치를 받고 있었습니다. 이제 0판이면 35%(탐색을 막지 않습니다), 10판 이상이면 85%입니다
- **수동 사전값 인계를 4판으로 단축**(v9는 8판). 실측값이 이미 자기 불확실성을 안고 있으므로 그 위에 수동값을 또 섞으면 삼중 계산입니다
- 결과 — 서폿 상위 5픽이 소나 86%, 말파이트 100%, 갈리오 73%, 마오카이 67%, 세라핀 80%로 정리됐고, 쉔(4판 25%)은 26위로 내려갔습니다. 원딜은 제리가 스몰더 위로 올라왔습니다. **탐색은 그대로 살아 있습니다** — 한 번도 안 해본 요네·코그모·이즈리얼은 여전히 각 라인 상위 3위 안에 있습니다

### 같은 챔이라도 라인이 다르면 다른 챔입니다

케넨은 미드 8판 25% / 탑 7판 43%, 아무무는 정글 8판 75% / 서폿 2판으로 갈립니다. 뭉뚱그리면 어느 쪽이 문제인지 영영 알 수 없습니다.

- 숙련 실측을 **라인별로 분리**합니다. 그 라인 표본이 6판에 이르면 전적으로 라인 성적을 쓰고, 그 전에는 전체 성적과 섞습니다. 확신도는 라인이 아니라 챔 전체 판수로 잡습니다 — 케넨을 15판 해봤다는 사실은 라인과 무관하게 "이 챔을 안다"는 뜻입니다
- 추천 카드 배지와 설정 화면도 지금 보고 있는 라인 기준으로 표시합니다(`★미드 3판 2승 (전체 4판)`)

### 첫 픽은 막지 않되, 한 번에 하나씩

처음 잡는 챔 42%(38판) vs 2~3판째 66%(44판) — **24%p** 차이입니다. v8은 "실패가 쌓인 것만 깎는다"며 첫 픽 감점을 0으로 뒀지만, 한 번도 안 해본 챔은 정의상 실측이 없으므로 이 손해가 영원히 값매김되지 않습니다. 분석 탭은 이미 "새 챔은 한 번에 하나씩만"이라 조언하고 있었는데 엔진이 그 조언을 따르지 않았습니다.

- 감점을 고정값이 아니라 **지금 몇 개를 동시에 벌이고 있는가**로 정합니다(최근 10판에서 새로 시작한 챔 종수). 벌여놓은 게 없으면 감점 0, 두세 개면 소폭 감점, 상한 6점이라 정말 좋은 신규 픽은 여전히 올라옵니다
- 감점이 붙을 때는 배지에 이유를 적습니다(`첫 픽 · 탐색 2종 진행중`). 이유 없이 깎이면 엔진이 고장난 것처럼 보입니다

### 그 밖에

- **`지금 추가` 버튼**: 내 라인 상대가 비었을 때 안내 문구가 곧 버튼입니다. v9.0에서 문구를 넣었지만, 안내만으로는 맞라인을 안 넣는 29%가 줄지 않습니다
- **등록만 해두고 안 쓰는 챔** 경고: 판이 없으면 실적이 등록값을 이길 수 없어 계속 추천 위쪽에 올라옵니다(실사용에서 1판 0%인 챔이 탑 4위였습니다). 엔진이 몰래 무시하는 대신 등록값을 손보라고 말합니다
- 배지 안의 숫자가 줄바꿈으로 쪼개져 `숙련 70→61`이 `70 · 61`처럼 읽히던 문제를 고쳤습니다

## v9.0 개선 (실사용 150판 전수 분석에서 나온 것들)

v8.4까지의 개선은 "이 추천이 이상하다"는 개별 신고에서 출발했습니다. 이번에는 실사용 전적 **150판(2026-07-03 ~ 08-08, 승률 54%)** 을 통째로 분석해, 개별 판에서는 보이지 않던 구조적 결함을 찾았습니다.

### 상성 축이 29%의 판에서 꺼진 채로 추천하고 있었다

가장 큰 문제였습니다. 적을 한 명이라도 입력한 146판 중 **42판(29%)** 에서 엔진이 내 라인 상대를 찾지 못해 상성 축이 통째로 중립(50)으로 죽었고, **21판**은 폴백이 엉뚱한 챔을 라인 상대로 세웠습니다 — 정글인데 다리우스, 서폿인데 베이가를 상대로 보고 계산했습니다.

원인은 "이 라인을 주 라인으로 쓰는 적"을 **한 명씩 독립적으로** 찾는 방식이었습니다. 상대가 3~4명만 입력됐거나 플렉스 픽이 섞이면 아무도 매칭되지 않고, 그러면 입력 순서상 처음 걸리는 챔을 집었습니다.

- **적 픽 전체를 5라인에 한 번에 배정합니다.** 적은 최대 5명이므로 순열 전수탐색으로 전역 최적을 찾습니다(P(5,5)=120). 다리우스가 탑에 배정되면 정글 자리는 자연히 다른 챔에게 갑니다 — 한 명씩 볼 때는 나오지 않던 답입니다. 실데이터 검증: 오배정 6건이 교정됐고(미드 상대를 갈리오→제드, 서폿 상대를 모르가나→나미), 나머지 21건의 임의 폴백은 신뢰도 등급이 붙었습니다
- **배정 신뢰도를 상성 계산에 곱합니다.** 억지로 끼워 맞춘 배정이 확신에 찬 점수를 만들지 않도록, 근거가 약하면 점수도 약하게만 움직입니다. 적합도 20 이하는 아예 상대로 치지 않습니다
- **부분 입력 보정**: 내 라인 자리가 비면 다른 라인에 배정된 챔 중 겸업 가능성이 가장 높은 챔을 후보로 남기되, 본업이 따로 있는 만큼 신뢰도를 깎습니다
- **적 칩에 배정된 라인을 표시합니다.** 배정이 틀렸을 때 알아챌 수 있는 유일한 단서입니다 — 그동안 배정은 조용히 일어났고, 🎯 지정은 150판 중 5판(3%)에 그쳤습니다. 이제 추정을 먼저 보여주고 틀렸을 때 고치게 합니다
- 상성 축 상한도 낮췄습니다. 팀 단위 상성 항목들(고기동·락다운·폭딜)은 대개 같은 조합을 다른 각도에서 세는 것이라 그대로 누적되면 96까지 올라갔는데, 실측에서 상성 65점 이상 구간의 승률은 54%로 **상성이 죽은 구간(62%)보다도 낮았습니다**. 방향은 남기고 확신만 깎았습니다(최대 78)

### 15판 33%인 챔이 아직 숙련 53점이었다

v8.0에서 "실적이 수동 설정을 끌어내린다"고 고쳤지만, 실제로는 꼬리가 너무 길었습니다. 케넨은 15판 33%인데 적용 숙련 52 — 여전히 중립 위였습니다.

- **8판이면 수동 사전값을 완전히 버립니다**(기존 `n/(n+4)`는 15판에도 21%가 남았습니다). 사전값은 판이 없을 때 쓰라고 두는 것이지, 실적을 이길 근거가 아닙니다
- **실측 스프레드를 표본 크기의 함수로** 바꿨습니다. 고정 폭을 쓰면 아무리 판이 쌓여도 신호가 좁은 띠에 갇힙니다. 3판짜리 인상은 여전히 조심하되 15판이면 실적을 그대로 믿습니다
- **승패 스프레드를 넓혔습니다**(0.68/0.32 → 0.74/0.26). 성과 등급은 28%, KDA는 0%만 입력됐으므로 대부분의 판에서 승패가 유일한 신호인데, 좁은 스프레드가 그 신호까지 누르고 있었습니다
- 결과: 케넨 52 → **45**, 소나(7판 86%) 60 → 59, 갈리오(11판 73%, 미등록) 55 → 58

### 성과 입력의 72%가 마찰로 사라지고 있었다

150판 중 성과 등급은 42판(28%), KDA는 **0판**이었습니다. 숙련도 학습의 절반이 입력 마찰로 죽어 있었던 셈입니다. 원인은 순서였습니다 — 성과를 **미리** 고른 뒤 승/패를 눌러야 했는데, 판이 끝난 직후의 자연스러운 행동은 승/패 한 번 누르는 것입니다.

- **기록한 다음에 물어봅니다.** 승/패를 누르면 방금 저장된 판을 가리키며 `오리아나 승 — 내 성과는?`이 뜨고, 한 번 탭하면 그 기록에 바로 반영됩니다. 건너뛰어도 됩니다
- KDA 입력칸도 이 줄로 옮겨, 쓰지 않는 입력이 상시로 자리를 차지하지 않게 했습니다
- 그 판에서 엔진이 **누구를 라인 상대로 보고 계산했는지**(`lanerAuto`, `lanerConf`)를 함께 기록합니다. 나중에 상성 판정을 되짚으려면 필요합니다
- 라이트 테마에서 선택된 성과 등급과 `⚠ 팀 문제` 버튼이 선택 표시를 잃던 버그를 고쳤습니다(팀 문제는 흰 글자가 흰 배경에 묻혀 아예 보이지 않았습니다)

### 엔진이 자기 성적표를 냅니다

추천 점수가 실제 승률과 같은 방향으로 움직이는지를 **앱이 스스로 보여줍니다**. 실측에서는 61~63점 구간이 72%인데 64점 이상은 53%로 역전돼 있었습니다. 이런 건 숨길수록 손해입니다.

- **추천 점수 → 실제 승률** 카드: 점수 구간별 승률과 상·하위 절반 비교. 방향이 뒤집혀 있으면 "지금은 점수를 절대 기준이 아니라 후보를 좁히는 용도로만 쓰세요"라고 그대로 말합니다
- **내 라인 상대를 알고 있었나** 카드: 상성 축이 실제로 켜져 있던 판의 비율. 저장값이 아니라 지금 엔진으로 다시 배정해서 세므로, 엔진을 고칠 때마다 이 숫자가 따라 움직입니다
- 피로도 분석을 **달력 날짜 → 연속 세션**(3시간 이상 쉬면 새 세션)으로 바꿨습니다. 자정을 넘겨 이어서 한 판이 두 날로 쪼개지면 그 세션의 5·6판째가 다시 1판째로 세어져 신호가 지워집니다. 바꾸고 나니 실사용 데이터에서 세션 1–2판째 57% → 5–6판째 **39%** 가 드러났습니다
- 무너지는 판수를 `7판째 이후`로 못 박지 않고 **데이터에서 읽습니다**. 사람마다 다르고, 이 사용자는 5판째였습니다(기존 규칙으로는 아무 경고도 뜨지 않았습니다)

## v8.4 개선 (실제 상성 데이터를 엔진에 반영)

"탈론으로 오리아나를 파고들어 응징이 가능하냐"는 실사용 질문에서 출발. 확인해보니 엔진이 **가이드가 명시한 진짜 카운터보다 탈론을 더 높게** 평가하고 있었습니다.

| 후보 | 이전 | 현재 | 가이드 판정 |
| --- | --- | --- | --- |
| 신드라 | 50 | **64** | ✅ 오리아나 카운터 |
| 이렐리아 | 45 | **59** | ✅ 오리아나 카운터 |
| 야스오 | 40 | **54** | ✅ 오리아나 카운터 |
| 탈론 | 60 | 53 | 카운터 아님 |

- **가이드 카운터 데이터를 상성 계산에 반영**(±14 = 클래스 매트릭스 최대치와 동급). 139챔 × 3상성의 실데이터가 추정을 대체합니다
- **실데이터가 있을 때 클래스 추정을 절반으로 감쇠**: 상대의 카운터 목록을 아는데 내가 거기 없다면, '암살자>메이지 +14' 같은 추정만으로 우위를 주지 않습니다. 불리 판정은 그대로 둡니다
- **근접 vs 장거리 진입 게이팅**: 기동기 없는 근접 챔이 장거리 견제형을 상대할 땐 "파고들어 응징"이 아니라 "접근만 하면 유리하나 진입이 어려움"으로 표시합니다

## v8.3 개선 (전술 브리핑)

추천 카드마다 `▾ 전술 보기`를 누르면 운영·상성 정보가 펼쳐집니다.

- **이 판**: 라인 상대와의 상성, 파워 커브, 아군 연계, 상대 위협 — 엔진이 이 드래프트에서 실제로 계산한 값
- **이 챔은 / 운영 / 상성**: WildRiftFire 챔피언 가이드(139챔)에서 뽑은 요점. **전부 한글로 표시**합니다 — 영문 원문을 통째로 번역하면 오역 위험이 커서, 가이드에 반복 등장하는 표현만 골라 한글 전술 문장으로 변환합니다(요약 131/139, 운영 136/139). 매칭이 없으면 억지로 채우지 않고 비웁니다
- **콤보·아이템 수치는 담지 않습니다.** 패치마다 바뀌고 틀리면 실전에서 손해이므로, 원문 가이드로 바로 가는 링크를 제공합니다
- `scripts/fetch-guides.mjs` + 주간 워크플로로 자동 갱신합니다. 가이드 URL slug는 추측하지 않고 통계 payload가 알려주는 값을 씁니다(이름에서 만들면 틀립니다 — `Nunu & Willump` → `nunu-amp-willump`)

## v8.2 개선 (목표 설정 — 전 포지션 숙련)

분석 탭이 단기 승률만 보고 "약한 라인을 줄이세요"라고 조언했습니다. **모든 포지션을 잘하고 싶다**는 목표와는 정면으로 충돌합니다. 앱이 목표를 알도록 고쳤습니다.

- **목표 설정**: 설정 화면에 `전 포지션 숙련`(기본) / `승률 우선` 선택을 추가했습니다. 추천 점수 계산은 동일하고 **분석 탭의 조언만** 달라집니다
  - 전 포지션 숙련: 라인을 버리라고 하지 않고, **그 라인 안에서 무엇을 남기고 무엇을 정리할지** 짚어줍니다 — "원딜은 라인이 아니라 챔 문제입니다"
  - 승률 우선: 기존처럼 잘 되는 라인에 집중하라고 안내합니다
- **라인별 성장과 주력 정리 카드**: 라인마다 전반 → 후반 승률 추이(↑↓)와 유지/정리 후보 챔을 한 화면에 보여줍니다. 실사용 데이터 예: 탑 45%→70%↑(말파이트 100% 유지 / 쉔 33% 정리), 원딜(제리 71% 유지 / 스몰더 0% 정리)
- 한국어 조사 처리기(은/는, 이/가, 을/를)를 추가해 라인 이름 뒤 조사가 자연스럽게 붙습니다

## v8.1 개선 (라인전 사거리 · 팀 변수 보정)

- **라인전 사거리 축 추가**: 와일드리프트는 라인전이 승패를 크게 좌우하는데, 엔진이 챔피언을 근접/원거리 둘로만 봐서 **같은 원거리끼리는 전부 동일 취급**했습니다. 오리아나(장거리 공 배치) 상대로 케넨(단거리)이 겪는 손해를 인식하지 못한 원인입니다. 사거리 등급(장/보통/단)을 도입해 라인전 상성에 반영합니다 — 검증: 케넨 vs 오리아나 카운터 44(불리), 오리아나 vs 케넨 62(우위). 정확한 수치는 패치마다 바뀌므로 **방향이 확실한 챔만 등재**하고 나머지는 보통으로 둡니다
- **팀 문제 표시**: 트롤·잠수·역할 미준수로 진 판을 `⚠ 팀 문제`로 표시하면 **그 패배가 챔피언 평가에서 제외**됩니다(중립 처리). 승리는 표시해도 그대로 반영합니다. 자기 신고는 편향되기 쉬우므로 분석 탭에 **표시 비율을 그대로 노출**하고, 40%를 넘으면 경고합니다
- **원딜 서폿 변수 분석**: 아군 픽에 엔첸터·탱커가 있었는지로 봇 라인 변수를 **객관적으로** 측정합니다(자기 신고 아님). 실사용 데이터에서 서폿류 있음 55% vs 없음 20%로 갈렸습니다

## v8.0 개선 (숙련도는 실적으로 결정된다)

설계 원칙: **탐색은 막지 않고, 실패가 쌓인 것만 깎는다.**

- **수동 숙련도 → 사전값(prior)으로 격하**: 예전에는 설정에서 정한 값이 실제 성적을 완전히 덮어썼습니다. 13판 38%인 챔이 계속 70점으로 추천되던 원인입니다. 이제 판이 쌓일수록 실측으로 수렴합니다(4판이면 절반, 12판이면 75%가 실측). 예: 케넨 등록 70 → **적용 53**
- **KDA를 성과 신호로 사용**: `(K+A)/D`를 포화 함수로 환산해 성과 등급과 함께 반영합니다. **승리와 개인 성과는 각각 독립적인 플러스 신호**로 다룹니다 — 이긴 판은 성과가 나빠도 깎이지 않고(하한 보장), *졌지만 12/2/8*은 중립 위(0.61)로 올라가며, 지고 성과도 나쁠 때만(0.20) 내려갑니다
- **첫 픽 감점 제거**: 메타가 좋은 새 챔은 그대로 상위에 올라옵니다. 시도를 막으면 주력이 늘지 않고 현재 챔폭에 갇힙니다. `첫 픽` 배지는 정보로만 유지하고, 손해는 *해본 뒤 성과가 나빴다*는 실측으로만 반영합니다
- **조정 내역 투명화**: 추천 카드에 `숙련 70→53` 배지, 설정 화면에 `→ 실적 53 (13판)` 표시
- **자동 백업 복구**: 실패 원인을 구분해 표시하고(파일 없음 / 권한 / 잠김), 재연결이 실패하면 **새 파일 지정**으로 넘어갑니다. 예전에는 모든 실패가 "권한 끊김"으로 표시되고 옛 파일만 재시도해 빠져나올 수 없었습니다

## v7.3 개선 (전적 보호)

과거 전적이 조용히 사라질 수 있는 경로를 모두 막았습니다.

- **복원은 덮어쓰지 않고 합칩니다**: 예전에는 백업을 불러오면 현재 기록을 통째로 교체해, 오래된 백업을 복원하면 그 뒤에 쌓인 판이 전부 사라졌습니다. 이제 판 시각을 키로 병합하며 중복은 건너뜁니다(성과·KDA는 기록된 쪽을 남김)
- **되돌리기**: 복원·전체삭제 직전 상태를 스냅샷으로 남겨 실수로 지워도 복구합니다. 전체삭제는 2단계 확인을 거칩니다
- **알 수 없는 챔피언도 보존**: 챔피언이 이름 변경·삭제되면 해당 판이 마이그레이션에서 영구히 버려졌습니다. 이제 원본 값을 `pickRaw`로 남겨 판수를 지키고 나중에 복구할 수 있습니다
- **저장 실패를 알립니다**: 저장 공간이 가득 찼거나 시크릿 모드일 때 기록이 조용히 유실됐습니다. 이제 상단 경고와 함께 즉시 백업을 유도합니다
- 시드 전적도 덮어쓰기가 아닌 병합으로 적재합니다

## v7.2 개선 (자동 백업)

- **자동 백업**: 전적이 브라우저 저장소에만 남아 기기를 벗어나지 못하고, 백업도 매번 수동이라 실제로는 잘 안 하게 되는 문제를 고칩니다. 파일을 **한 번만 지정하면** 이후 판을 기록할 때마다 같은 파일에 자동 저장됩니다(File System Access API, 데스크톱 Chrome·Edge). 브라우저를 다시 열어 권한이 초기화되면 `다시 연결` 버튼으로 복구하며, 그동안에도 앱 동작에는 영향이 없습니다
- 미지원 브라우저(모바일·Safari 등)를 위해 **복사** 버튼을 추가했습니다 — 백업 JSON을 클립보드로 바로 가져갑니다

## v7.0–7.1 개선 (개인 성과 학습 · 분석 탭)

실사용 전적 102판을 분석해 나온 문제를 고칩니다.

- **개인 성과 기록(MVP·SVP·KDA)**: 승패는 팀 단위 결과라 10판 규모에선 거의 노이즈입니다. "졌지만 내가 SVP"는 픽이 맞았다는 강한 증거이므로 승패와 분리해 기록하고, 숙련도 학습에 이 신호를 씁니다
- **숙련도 산식 교정**: 기존엔 판수가 가산점이라 *많이 지고 있는 챔도 숙련도가 높게* 나왔습니다(실측: 13판 38% 챔이 54점). 이제 판수는 추정의 확신도로만 쓰고 실제 성과가 점수를 결정합니다(같은 챔 → 48점)
- **메타 중심 모드의 숙련 반영**: 기존엔 숙련 가중치가 **0**이라 엔진이 매판 새 챔을 추천했습니다. 실측상 처음 잡는 챔은 2~3판째보다 승률이 크게 낮은데, 이 손해를 사용자가 그대로 떠안고 있었습니다. 이제 메타가 주도하되(35%) 익숙한 픽이 동점을 깹니다
- **첫 픽 경고**: 한 번도 안 해본 챔에 `첫 픽` 배지와 소폭 감점(승률 약 2%p 우위가 있어야 추천). 좋은 신규 픽은 여전히 올라옵니다
- **자기 측정**: 전적 화면에 엔진 버전별 승률을 추가해 "패치 후 나빠졌나"를 인상이 아니라 데이터로 확인합니다
- **분석 탭**: 전적 화면이 `기록` / `분석` 두 탭으로 나뉩니다. 분석 탭은 이항검정으로 **최근 부진이 정상 변동인지 유의한 하락인지 먼저 판정**하고(10판 30%는 대개 정상), 실행 가능한 개선점을 표본 크기와 함께 제시합니다 — 입력 성실도별 승률, 챔피언 경험도, 라인 집중도, 하루 N판째 피로도, 챔폭 점검. 8판 미만 구간은 흐리게 표시해 단정하지 않습니다

## v6.1 개선 (랭크 구간 선택 · 밴 추천)

- **랭크 구간 선택**: Diamond+ / Master+ / Challenger 통계를 탭 한 번으로 전환합니다. 선택은 저장되어 다음 방문에도 유지되고, 구간 전체가 payload에 담겨 있어 재요청 없이 즉시 바뀝니다
- **밴 추천**: 표본 보정 승률 + 픽/밴 존재감 + 상승 추세로 위협 점수를 계산해 상위 3챔을 제안합니다. 내 라인에서 만나는 챔은 가중하고, 내 주력(수동 숙련도 또는 전적 기반)을 카운터치는 챔은 가산합니다. 제안을 탭하면 바로 밴 목록에 들어갑니다
- **추세 기준선 버그 수정**: 구간 전환 시 추세를 반드시 같은 구간끼리 비교합니다. 이전에는 Master+ 현재치가 Diamond+ 기준선과 비교되어 '구간 차이'가 '패치 변화'로 표시될 수 있었습니다
- **원격 데이터 신뢰 경계**: `data/latest.json`은 서드파티 페이지에서 자동 수집되므로, 앱이 채택 전 전체를 정규화합니다(필드 형식·범위 검증, 앱 DB에 없는 챔피언 제거, 라벨/키 화이트리스트). 파이프라인에서도 같은 검증을 수행해 오염 데이터가 커밋되지 않게 막습니다
- 구간 선택기를 DOM API로 조립하고, 버튼 재생성 시 키보드 포커스를 복원합니다

## v6.0 개선 (상성 엔진 개편 — 실전 오추천 수정)

실사용 보고에서 출발: 미드에서 상대가 **아리**인데 **탈론**이 추천됨(라인 삭제 수준의 역상성). 원인은 클래스 매트릭스의 '암살자>메이지 +2'가 아리처럼 **기동기+CC를 가진 메이지에겐 정반대**라는 것.

- **기동·셀프피어 조정**: 암살자↔물몸 원거리 상성에서 상대의 도주기(mob)·하드CC·점착CC 보유량만큼 클래스 우위를 상쇄/역전. 부동 메이지(신드라·직스) 상대 암살자 우위는 유지, 아리류 상대는 역카운터로 판정
- **아리 KIT 교정**: 궁 3연속 이동을 `mob:2`로 반영 (기존 미인식)
- **'파고들어 응징' 게이팅**: 기동성 2 이상 상대는 파고들어도 못 잡음 — 보너스 대신 감점
- **유명 상성(PAIR) 확장**: 3항목 → 미드(아리>탈론·제드·카타리나, 피즈>아리, 갈리오>AP암살자, 카사딘>부동AP)·서폿(모르가나>그랩류)·탑(피오라>방템탱커) 등 방향이 확실한 정설만 보수적으로 등재
- **회귀 테스트**: PAIR/KIT 키가 로스터에 실존하는지 검증 + 아리>탈론 등재·기동 게이팅 존재를 스모크에 고정

## 데이터 파이프라인

```bash
node scripts/fetch-stats.mjs
```

WildRiftFire 통계 페이지에 인라인된 JSON 페이로드를 받아 세 곳에 씁니다.

| 산출물 | 용도 |
| --- | --- |
| `data/latest.json` | 앱이 실행 시 받아오는 최신 통계 (랭크 구간 3종 + 추세 기준선) |
| `data/history/<날짜>.json` | 업스트림 갱신일 기준 아카이브, 추세 기준선의 출처 |
| `stats.js` | 앱 셸에 번들되는 오프라인 폴백 (Diamond+) |

챔피언 가이드는 따로 수집합니다(패치 때나 바뀌므로 주 1회).

```bash
node scripts/fetch-guides.mjs
```

`data/guides.json`에 챔피언별 한글 전술 요점·카운터·궁합을 씁니다. `--from <디렉터리>`로 미리 받아둔 HTML을 파싱할 수 있고, 수집 성공률이 50% 미만이면 기존 파일을 덮지 않습니다(사이트 구조 변경 시 데이터 보호). `.github/workflows/update-guides.yml`이 매주 월요일에 실행합니다.

`--from <파일>`로 저장된 페이지를 파싱하거나 `--dry-run`으로 쓰기 없이 점검할 수 있습니다. 챔피언 DB에 없는 신규 챔피언이 나오면 해당 행만 건너뛰고 종료 코드 2와 함께 이름을 출력하며, CI는 이를 경고로 표시하되 나머지 갱신은 계속 진행합니다.

`.github/workflows/update-stats.yml`이 매일 04:20 UTC(13:20 KST)에 이 스크립트를 실행하고, 스모크 테스트를 통과하며 실제 변경이 있을 때만 커밋합니다. Actions 탭에서 수동 실행도 가능합니다.
