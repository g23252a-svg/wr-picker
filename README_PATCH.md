# WR Picker v20.0.0 패치

전체 기능과 실행·검증 방법은 [README.md](README.md)를 참고하세요.

실사용 전적 **336판**(65판 추가, ~10-29)으로 먼저 진단했습니다 — 최근 40판 57.5%, 지금은 부진 구간이 아닙니다. 그래서 이번 패치는 **앱 자체를 8개 관점에서 전수 감사**한 결과입니다. 60건 중 재현되는 **48건**을 고쳤습니다.

## 2. 분석이 잘못 재던 것

- 같은 10판에 배너는 한쪽 꼬리(4% 나쁨), 진단 카드는 양측(27% 분산) → 배너 양측
- 라인 항목 **이중 보정**(×35), 패치 항목 **무보정** → 가족 하나로 p 와 필요 판수 통일
- 상대 라인 배정을 오늘 통계로 다시 하던 진단 → 자기 채점의 그 판 당시 배정 재사용
- 밴 추천 '내 주력'이 수동 챔폭 기준(쉔 1승 4패 보호) → 엔진과 같은 숙련값
- 챔폭을 바꿔도 자기 채점 캐시가 그대로 → 키에 챔폭 서명
- 손에 익은 픽의 '익숙함'이 전체 판수(미드 갈리오가 서폿에서 올라옴) → 이 라인 판수

## 3. 신뢰 경계

- **가이드 XSS**(CDN·캐시·sw 프리캐시 → innerHTML/href) → `sanitizeGuides` + `esc`
- `byEn['constructor']` 가 참 → 조회표를 프로토타입 없는 객체로, 원격 키는 `hasOwn`
- 백업의 아무 필드나 저장(`Object.assign`), `t=1e20` 이면 **드래프트 화면이 멈춤** → 화이트리스트·형식·범위 검사
- 저장값 `"__proto__"` 키, 날짜 모양만 맞는 `updated`

## 4. 백업·복원 — 0바이트 백업의 정체

사용자의 `wr-picker-backup_7.json` 이 0바이트였습니다. 앱에서 0바이트 백업이 나오는 유일한 경로는 **자동 백업 켜기**: 파일 선택기가 빈 파일을 만들고, 첫 저장이 실패해도 "켰습니다"가 떴습니다.

- 첫 저장 성공 뒤에만 '켜짐', 실패하면 원인과 "파일은 비어 있습니다"
- 전체 삭제 → 다시 열면 시드 271판이 되살아나던 것(시드 도입 전 기기) 차단
- 전체 삭제가 자동 백업 파일을 빈 목록으로 덮어쓰던 것 → 그 한 번은 건너뜀
- 되돌리기가 가져오기를 못 되돌리던 것("0판 복구") → 가져온 판을 뺌
- `pickRaw` 가 다음 부팅에서 지워지던 것 → 보존 + DB 복구 시 실제 되살림

## 5. 파이프라인

- 추세 기준선을 **구간별**로(Challenger/Legendary 가 7.3a 내내 추세 없이 "기록 없음"이던 것)
- 푸시 거절 시 그날 데이터 영구 손실(9-22, 10-03 실제 발생) → 리베이스 재시도 + 아티팩트
- '변경 없음' 판정이 untracked `fetch.log` 때문에 한 번도 안 걸려 빈 커밋으로 실패(10-27 실제) → 산출물만 본다
- `updated` 역행 보호, 모르는 챔 행 아카이브 보존, by-patch 상한을 패치 수 비례로(열 패치 뒤 봇이 멈출 뻔)

## 6. 테스트

정규식 검사가 **리플레이 오늘 통계 채점·사후편향·추세 중심화 제거** 돌연변이를 전부 통과시키고 있었습니다. `tests/engine.mjs` 로 엔진을 vm 에 올려 실제 값을 봅니다.
